## Outcome

An agent can produce the same named views and a capture report without asking the owner to position a camera manually.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Define fixed seed/settings/poses, output names and a GPU-required command. Use the selected engine with a real renderer, not --headless.
2. Capture after rendering/streaming readiness; include build, world version, actual pose and hardware/renderer data in the report.
3. The Python wrapper validates prerequisite/output failures and retains images under artifacts; it does not declare them beautiful.

## Acceptance

- Missing GPU/display/capture output gives NOT RUN/failure, never an empty-image pass.
- Produce readable screenshots of the real terrain on a supported graphical runner; record that later content changes require recapture.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No image-generation service, image-diff pixel equality across GPUs or subjective auto-approval.

## Stop conditions

A real graphical capture environment is unavailable. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
