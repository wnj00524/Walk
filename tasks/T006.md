## Outcome

The application can represent locations on both sides of the origin without confusing map cells with renderer coordinates.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Implement C01 normalisation with signed integer cells and local offsets. Keep operations independent of scene nodes.
2. Read the frozen coordinate fixture from the repository through a test-only loading path or copy it reproducibly to test fixtures without changing its values.
3. Reject non-finite offsets. Explain negative floor and metre units in code.

## Acceptance

- Every fixtures/coordinate_vectors.json example passes.
- Test repeated boundary crossings, positive and negative offsets, and invalid/non-finite input; no guessed floating-origin integration.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite coordinates` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.
