## Outcome

Corrupt, interrupted or incompatible saves do not silently move the owner into a different world.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Finish tested temporary-write/replace/backup handling using the pinned OS/engine APIs.
2. Validate schema, generator/content versions, integer bounds, finite numbers and missing assets before restore.
3. Preserve rejected input and provide a readable recovery choice; never automatically overwrite it with a new world.

## Acceptance

- Exercise corrupt/truncated files, simulated write failure, unsupported versions, missing content and repeat save/load.
- Verify the previous good save survives failure and accepted saves restore after collision readiness.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite save` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.

## Non-goals

No cloud sync, automatic regeneration migrations or deleting saves during cache cleanup.

## Stop conditions

Atomic-replace behaviour differs on the target platform and lacks an explicit tested fallback. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
