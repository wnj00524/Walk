## Outcome

A single command imports the project and runs one real test suite with reliable error reporting.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Resolve GODOT_BIN and check the reported version against the candidate lock. Use subprocess argument arrays, timeouts and explicit exit handling.
2. Run import first, then the selected registry suite. Capture logs under artifacts and reject import/script errors, crash, zero tests, unknown suite and timeout.
3. Use fake subprocess results only in the Python wrapper tests; the actual smoke suite invokes Godot.

## Acceptance

- Missing binary and timeout exit nonzero and explain the missing prerequisite.
- Known import error text fails even with an exit-0 fixture; normal smoke passes with an actual executed count.
- Run wrapper unit tests and python tools/check_game.py --suite smoke.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite smoke` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.

## Non-goals

No installer, dependency upgrades, GPU testing or paid calls.

## Stop conditions

The wrapper cannot distinguish absence/failure from success. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
