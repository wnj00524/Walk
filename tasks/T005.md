## Outcome

The owner can look around and walk on an explicitly labelled simple test floor.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Use a CharacterBody3D and Camera3D with named input actions, metre/second settings and bounded pitch.
2. Support mouse capture/release and Escape without trapping the cursor. Disable head bob and stamina.
3. Keep the floor in the prototype scene only. Document input mappings and safe comfort settings.

## Acceptance

- Check pitch limits, settings validation and frame/physics-step-independent motion in a focused test.
- Perform a graphical walk/look/cursor-release check. No real terrain readiness is claimed yet.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite player` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.

## Non-goals

No body animation, jumping puzzles, inventory, fall damage or full settings UI.

## Stop conditions

Movement needs broader app changes or a graphics check is unavailable. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
