## Outcome

A guarded development command can create/reuse a named Meshy request and safely download a completed result; testing spends nothing.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Verify the current official endpoint/request schema and record the API version in the feature guide.
2. Implement dry-run by default, environment-key reading, explicit approved execute mode, receipt persistence, bounded status polling and size/hash-checked download.
3. Separate request transport so tests supply fixture responses. A timed-out paid submission becomes SUBMISSION_UNKNOWN, not a retry. If this exceeds the task-size limit, split transport, lifecycle and CLI before dispatch.

## Acceptance

- Offline tests cover missing key, disabled budget, duplicate request, pending/success/failure, 401/402/429, timeout, corrupt/oversized download and resume with the same known task ID.
- No real request occurs in a routine test or dry-run. Live asset proof is T019.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No bulk generation, remote deletion, automatic paid retries or runtime client.

## Stop conditions

Current API details cannot be verified, or an accepted request cannot be reconciled safely. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
