## Outcome

Sound effects can be generated by a guarded development command with zero-cost routine tests.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Verify the current sound-effects endpoint, request body, response type and supported output formats.
2. Use explicit batch approval and execute mode, masked secrets, bounded download and atomic local output promotion.
3. Handle ambiguous paid timeouts without automatic re-submission; do not invent an async job API.

## Acceptance

- Offline tests cover disabled budget, missing key, rate limiting, server failures, response interruption and invalid audio output.
- Dry-run never makes a paid request; preserve local request receipts for reconciliation.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No narration, music service, voice cloning or runtime HTTP calls.

## Stop conditions

A response format requires an unapproved conversion dependency. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
