## Outcome

The project either has an accepted scriptable streaming foundation or stops dependent work with a precise reason.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Review the actual code, required platform export/load evidence, streamed walking and large-coordinate results.
2. Require any contract operation not yet implemented to be completed in a small child task before acceptance.
3. Record accepted versions, tested envelope and limits. Set the backend_gate check true only when all foundation criteria pass.

## Acceptance

- A Windows exported prototype runs; terrain/collision stream; the accepted coordinate strategy preserves identity; setup needs no manual scene editing or engine compilation.
- No missing requirement is converted into a pass because a probe task was completed. A rejection keeps this gate BLOCKED.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No beautification, large asset batches or replacing infinity with a bounded map.

## Stop conditions

Any foundation criterion lacks accessible evidence. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
