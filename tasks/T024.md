## Outcome

The owner approves a genuinely generated place worth walking through, before additional scope is layered onto it.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Capture the fixed seed set plus a pre-recorded unselected seed, including close ground views and a real walking clip.
2. Apply the qualitative rubric and compare return-trip continuity.
3. Translate revisions into one bounded task each; do not mark the gate DONE while required revisions remain.

## Acceptance

- Owner approval refers to a specific build and seed set, not an asset preview or manually composed fixture.
- Record performance observations separately and do not label them a completed performance gate.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No passing by screenshot alone when motion shows defects; no adding more biomes to distract from quality issues.

## Stop conditions

Unavailable owner review or unmet visual acceptance. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
