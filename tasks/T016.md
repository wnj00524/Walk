## Outcome

Agents can list approved/requested assets and detect invalid records before making any paid call.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Implement C06 record validation with no external packages. Keep the shipped catalogue empty until real approval.
2. Add three request-only examples: a rock, a tree and ground cover. Use stable IDs and documented dimensions; do not claim files exist.
3. Validate budget approval, file confinement, lifecycle transitions and prompt/config hashes.

## Acceptance

- Reject duplicate IDs, missing paths in approved records, traversal paths, invalid states and enabled budgets without named request limits.
- The example budget authorises zero real jobs; all tests are offline.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No provider network code, asset generation or invented runtime placeholders.

## Stop conditions

Asset requirements need an unapproved external tool or ambiguous spend policy. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
