## Outcome

Agents can run a named headless test suite and distinguish success, failure and an empty selection.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Implement an explicit suite registry and a small assertion/result collector. Parse the --suite argument after Godot user arguments.
2. Add smoke checks for the main scene and an intentionally failing fixture selected only by an explicit self-test option.
3. Print executed/passed/failed counts. Use explicit exit codes; do not rely solely on disabled-in-release assertions.

## Acceptance

- smoke executes at least one assertion and exits 0.
- A wrong expected value, unknown suite and empty suite each produce nonzero exit codes. The intentionally failing fixture is not in the normal passing suite.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- At this bootstrap stage, run the pinned editor directly: `godot --headless --path game --script res://tests/run_tests.gd -- --suite smoke`. T004 adds the wrapper later.

## Non-goals

No external test framework or runtime feature development.

## Stop conditions

Cannot prove failing tests fail; do not proceed to later implementation. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
