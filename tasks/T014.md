## Outcome

Future changes cannot quietly break shared terrain edges or regenerate a different place on return.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Use the accepted surface/graph sampling path, not a duplicate approximate height function.
2. Create independently reviewed pinned-version sample expectations with recorded coordinates/tolerances.
3. Compare adjacent blocks, available detail levels, approach directions and repeat generation.

## Acceptance

- A controlled wrong offset or seed makes the suite fail.
- Shared boundary samples and return-trip samples meet recorded tolerances; visual detail-level seam checking is retained separately.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite terrain` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.

## Non-goals

No production generator rewrite or globally bit-identical GPU promise.

## Stop conditions

Expected samples cannot be justified independently of the changed implementation. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
