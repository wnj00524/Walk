## Outcome

Restarting returns the walker to the same world and logical position rather than generating a new world.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Implement C05 parsing and write/read for the current schema with exact integer-string handling.
2. Wire start/quit with the accepted terrain readiness path; do not place the player on unready ground.
3. Show a simple readable error for invalid/unsupported input and preserve it. Comprehensive interrupted-write tests are in T032.

## Acceptance

- Round-trip the example save, a negative cell and a large in-range cell; verify unsupported version and corrupt JSON are preserved and rejected.
- Actually close/reopen the graphical application and compare location/seed.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite save` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.

## Non-goals

No save browser, cloud sync or silent migrations.

## Stop conditions

The adapter cannot safely restore an arbitrary logical position. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
