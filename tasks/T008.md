## Outcome

The selected engine can load the real terrain dependency, and later agents have verified native names to call.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Install only the pinned prebuilt add-on/bundle. Retain its licence/version data; do not check arbitrary unreviewed binaries into the repo without the chosen dependency policy.
2. Write a minimal probe that constructs the required native classes and inspects/configures the intended built-in generator/graph, viewer, collision and diagnostic access.
3. Record exact API names, supported operations and actual platform results. Probe a Windows export for dependency loading when the runner is available.

## Acceptance

- Actual class construction and an import pass succeed without unknown property/method errors.
- The report distinguishes documentation lookup from executed native calls and identifies missing export/platform checks.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No terrain world, custom C++ changes, invented fallback methods or version upgrades.

## Stop conditions
