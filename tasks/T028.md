## Outcome

A deterministic intentionally shaped basin can hold a bounded water surface without water crossing arbitrary hills.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Specify basin owner ID, centre, extent and water elevation, then implement one supported native terrain modification recipe.
2. Make shared-boundary samples agree using canonical ownership and sufficient neighbour context.
3. Expose a water mask/elevation to presentation and traversal; do not require a hydrology simulator.

## Acceptance

- Basin and shoreline sample checks agree at neighbouring-cell boundaries.
- The water mask is stable on return and does not classify surrounding higher terrain as underwater.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite lakes` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.

## Non-goals

No rivers, drainage networks, erosion simulation or independent fake water terrain.

## Stop conditions

A basin cannot be expressed in the accepted backend without a new architectural dependency. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
