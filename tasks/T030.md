## Outcome

The owner can walk, pause, use optional auto-walk and recover from an unsafe position without game-like penalties.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Add validated sensitivity/FOV/auto-walk settings through the existing small interface; head bob remains off.
2. Use real collision readiness to pause unsafe advancement and provide a readable waiting state.
3. Treat deep-water/non-walkable positions as safe traversal limits, not an invisible game death; add return-to-last-safe-ground. Split comfort UI and recovery if too large.

## Acceptance

- Test slope/unsafe/readiness/recovery state changes without teleporting to a guessed zero floor.
- An actual walk checks cursor release, pause, water-edge handling and recovery.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite player` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.

## Non-goals

No stamina, damage, swimming, mandatory jumps or map/navigation mechanics.

## Stop conditions

Movement behaviour would conceal an unresolved terrain readiness defect. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
