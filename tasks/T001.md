Status is recorded only in PLAN.md. A WAITING card must pass the coordinator readiness check before implementation. Referenced future feature/source files must exist by then.

## Outcome

Another agent can obtain the exact same engine/add-on candidate without guessing. No game is claimed to exist.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Use official release pages to find a matching stable Godot 4 editor, matching export templates, and a prebuilt Voxel Tools candidate. Prefer a supported GDExtension; a prebuilt module edition is acceptable only with its matching templates. No source compilation.
2. Record exact versions, edition, download URLs, source revision where available, SHA-256 hashes of downloaded artifacts, supported platforms and actual binary version output. Do not invent checksums or claim a platform was tested when only its archive was found.
3. Record the Python version actually used. Write reproducible Windows instructions and any agent-runner setup separately. Keep candidate selection separate from later backend acceptance.

## Acceptance

- Run the acquired editor with --version and retain output; run the included documentation validator and helper tests. The candidate can be recorded with other-platform runtime checks explicitly NOT RUN.
- A reviewer can identify the exact editor/templates/add-on pair and each unverified part. All missing downloads/executions are declared.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No terrain implementation, asset generation, engine compilation, API keys or global machine changes.

## Stop conditions

No compatible prebuilt candidate, unavailable required download/execution, or a need to fabricate version facts. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
