## Outcome

The prototype produces recognisable gentle valleys/ridges rather than one undifferentiated noise surface.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Keep the accepted native generation path. Express a single modest landform recipe as parameters/resources the adapter actually supports.
2. Define every parameter in metres or another named unit and validate ranges. Do not introduce a second height model.
3. Produce fixed-seed views and rerun the terrain consistency suite. This is one recipe, not a complete biome/climate engine.

## Acceptance

- Invalid parameters fail explicitly; seeds reproduce the recorded landscape on the supported version.
- Boundary/return checks still pass and the owner can identify slopes/ridges/valley structure in recorded views.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite landform` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.

## Non-goals

No erosion simulator, global geology, rivers, caves or expanded world palette.

## Stop conditions

The recipe requires unsupported native graph operations or changes the accepted coordinate strategy. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
