## Outcome

The pinned editor opens a plain empty test application with a visible title and an orderly exit.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Create the Godot project, a text main scene and one small startup script. Set the main scene explicitly.
2. Use ordinary built-in nodes only. Add a simple visible label that identifies this as a prototype. No terrain dependency yet.
3. Document the exact launch/import commands and what the owner should see.

## Acceptance

- Run headless resource import with the pinned editor and retain all errors/output.
- Launch on an available graphical runner, see the prototype title and exit cleanly. If no graphics runner exists, record the visual check NOT RUN and obtain it before task acceptance.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No controller, menus, plugins or placeholder scenery presented as a landscape.

## Stop conditions

The chosen editor cannot import a minimal project, or graphical acceptance is unavailable. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
