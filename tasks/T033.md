## Outcome

Rendering density, streaming limits and optional generated caches have explicit bounded settings.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Define a small set of presets using actual supported controls; do not pretend every diagnostic exists.
2. Keep world identity/placement decisions separate from temporary draw density/detail. Quality changes must not rewrite saves.
3. Validate limits and record how each affects the walker. Generated cache is optional; if used, cap it separately from saves.

## Acceptance

- Reject invalid budgets; ensure quality changes preserve seed/location and agreed world content.
- Synthetic travel exercises eviction/residency; actual memory is measured by T035.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite quality` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.

## Non-goals

No automatic hardware benchmarking framework or silently changing the world to meet FPS.

## Stop conditions

A requested budget cannot be enforced or measured by the selected backend. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
