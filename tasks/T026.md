## Outcome

The project has reviewed local wind/foliage/water sound layers, not just mocked files.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Obtain an explicit finite audio-batch budget and use the guarded client.
2. Validate actual format/size/duration and listen for loop boundaries, artifacts and unwanted combined sounds.
3. Retain approved local files/hashes; reject narration/music or unexpected noise.

## Acceptance

- Owner listens to the actual files/loop demonstration and accepts or requests a bounded revision.
- No live service dependency remains in the approved catalogue.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No extensive catalogue, species-authenticity claims or mixing a whole forest into one loop.

## Stop conditions

No approved spend or no listening review. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
