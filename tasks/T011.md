## Outcome

Later low-capability agents receive exact terrain method signatures and states instead of making architecture decisions.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Read actual probe code and results. Define concrete signatures for configure, viewer update, readiness/surface queries, diagnostics and shutdown.
2. Define the accepted coordinate strategy, generation epoch handling, thread boundary, graph seed mapping and numerical comparison tolerances.
3. Name each required regression test and source owner. If probes are unsuitable, record rejection and keep T012 blocked rather than freezing a fictional working interface.

## Acceptance

- Every native capability used by the contract is supported by the recorded pinned-version probe.
- A reviewer can trace each public operation to an observed implementation or an explicitly bounded remaining task. Missing implementation means T012 cannot pass.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No new backend, feature implementation or silent change to save/world identity.

## Stop conditions

No demonstrated solution for continuity, coordinates or export; prepare a separate alternative spike. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
