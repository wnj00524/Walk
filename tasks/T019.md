## Outcome

The pipeline has three real, reviewed representative assets, or an explicit recorded quality failure before any large batch.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Obtain owner approval for an enumerated finite local budget; the pack default of zero remains blocking until approval.
2. Run the real Meshy workflow for the selected requests, retaining receipts and approved local files. Review close/mid/far views together.
3. Reject unsuitable results; propose a bounded regeneration or sourced compatible asset through the same import path. Record provenance and technical/aesthetic decisions.

## Acceptance

- Actual files exist and hashes match the catalogue; the owner accepts the specific rock, tree and small plant in the game lighting.
- No key, signed URL, raw service client or unreviewed fallback asset enters the runtime export.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No large catalogue, perpetual regeneration or pretending fixture models are final assets.

## Stop conditions

No approved spend, unsuitable tree/plant quality, or inaccessible owner visual review. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
