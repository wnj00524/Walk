## Outcome

The owner can launch an exported Windows build containing all approved content, with no network or development keys.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Use the locked editor/templates and an explicit export preset. Write outputs to artifacts/builds.
2. Inspect export inclusion rules so asset clients, receipts, raw generations, tests/secrets and local budgets are not shipped.
3. Run on Windows with network unavailable and no service-key variables; verify start/walk/save/quit/resume.

## Acceptance

- A real exported .exe runs on Windows; record build hash and accessible package location.
- The offline route succeeds and required approved assets are present. A Linux export operation alone is not a Windows launch test.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.

## Non-goals

No installer signing service, store integration, telemetry or runtime updates.

## Stop conditions

Missing Windows runner/templates, missing approved assets or any required runtime network request. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
