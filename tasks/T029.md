## Outcome

The walker sees water confined to the generated basin, with a coherent shore and distance behaviour.

## Read set

Read the root rules/orientation/recent log, then the metadata read set and actual files being changed. Read dependency evidence when its result fixes a version or interface. Do not read every task.

## Allowed changes

Only the metadata paths, plus this task's evidence report, its relevant feature walkthrough, CODE_GUIDE.md, its PLAN.md row and one appended DLOG.md row. Directory scopes are not permission for unlimited changes. Do not change rules/contracts unless explicitly listed.

## Steps

1. Consume the basin record; do not infer a new terrain/water height.
2. Use a simple bounded surface and documented material settings before considering elaborate reflections.
3. Release/recreate surfaces with their owner cells; keep water-related local audio optional until the mixer supports it.

## Acceptance

- Repeated loading does not duplicate water; the surface/mask remains within the intended basin.
- Actual shore/elevated views show no water cutting through unrelated hills or obvious gaps.
- Run `python tools/project.py validate` and the existing helper tests. Explain the changed code in ordinary language and update its feature walkthrough.
- After the suite exists, run `python tools/check_game.py --suite lake_rendering` and affected regression suites. This command is introduced by T004; T003 uses the direct Godot script command while bootstrapping.

## Non-goals

No swimming, boats, ocean system or mandatory custom reflection pipeline.

## Stop conditions

A material/shore defect needs a separate recipe or shader task. Also apply AGENTS.md: stop after two failed focused repairs, for unapproved spend, unavailable required evidence, or when the coordinator must split the scope.
